## 3. Repository README Improvements

Each project repo should have a polished README with:

- **Project name and one-liner** — Clear value proposition
- **Screenshots** — At least 2-3 showing the interface
- **Features list** — What it does (not just tech)
- **Tech stack badges** — Consistent styling
- **Live link** — If deployed
- **Setup instructions** — Clear and concise

## 5. Profile Polish

- **Avatar:** Use a professional photo or a clean logo. Avoid default GitHub avatar.
- **Bio (short):** Update to: "Building products — AI, discovery platforms, and developer tools."
- **Company:** Optional — leave blank or add your personal brand
- **Location:** Add if comfortable
- **Website:** `https://kaizokugws.com` or your personal site
- **Twitter/X:** Add if you use it

## 6. Repository Organization

- Add `README.md` to every repo (even private ones)
- Add `.gitignore` to every repo
- Add a license (MIT recommended for public repos)
- Use consistent repo descriptions

## 7. Activity & Contributions

- Commit regularly to keep the contribution graph active
- Star repos you find interesting (shows curation)
- Engage with issues on your own repos

## 8. SEO & Discovery

- Use topics/tags on repos (e.g., `nextjs`, `education`, `compiler`)
- Write descriptive repo descriptions
- The profile README itself helps SEO — keep it updated
